=========================================
COMMANDES DU PROJET
=========================================

= Commande unique avant de mettre en production (sur le poste de developpement)
composer preflight
= Necessite Apache/MySQL/Edge, dependances de developpement et identifiants HTTP de test.
= Compile les assets et lance tous les controles ; les tests utilisent des fixtures temporaires.
= S'arrete au premier echec. Ne publie pas et n'applique aucune migration.

= Diagnostic seul (aucune migration ni modification des donnees)
composer doctor

= Actualiser les tomes a venir (Mangacollec, invite)
composer manga:sync

= Installer/reinstaller l'actualisation Windows (09:00 et ouverture de session)
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Manga/install-schedule.ps1

= Journal de l'actualisation automatique
storage/logs/manga-releases-sync.log

= Sur un autre serveur : planifier quotidiennement depuis la racine
php scripts/Manga/sync-releases.php

= Correspondances des editions / nouvelles series ambigues
Config/manga-releases.php

= Exécuter depuis la racine du projet
C:\wamp64\www\lolissr

= Afficher les commandes Composer disponibles
composer run-script --list

= Profiler la recherche globale pour un utilisateur (lecture seule, MySQL requis)
composer search:profile -- 1

= Mesurer des recherches precises
composer search:profile -- 1 "a" "Berserk" "Berserk 1"

= Ajouter les listes paginees et les statistiques (lecture seule, sans cache HTTP)
composer search:profile -- 1 --lists

= Choisir les pages pour comparer les OFFSET (10 pages maximum, de 1 a 9999)
composer search:profile -- 1 "a" --pages=1,5,20

= Mesurer les lectures HTTP sur cinq passages, top 10 par mediane dans la console et le rapport HTML
composer http:profile

= Choisir le nombre de passages (1 a 20 ; seules les requetes GET sont repetees)
php tests/Http/run-http.php --repeat=10

= Temps HTTP avec reseau et session ; premier passage inclus, sans mesure du rendu navigateur
= Rapport : tests/Http/reports/lolissr-http-report.html

= Remplacer 1 par l'identifiant de l'utilisateur a mesurer

=========================================
MAINTENANCE
=========================================

= Vider logs / cache / sessions et régénérer l'autoload
composer dev:reset

= Vider uniquement les logs
composer logs:clear

= Vider uniquement le cache
composer cache:clear

= Supprimer les sessions et déconnecter les utilisateurs
composer sessions:clear

= Auditer les miniatures sans modifier les fichiers
composer images:optimize

= Redimensionner et compresser les miniatures avec sauvegarde des originaux
composer images:optimize -- --apply

= Cette commande génère aussi les variantes .grid de 600 px pour les collections
= Générer uniquement les variantes, en conservant les images principales
composer images:variants -- --apply

= Après ajout, remplacement ou suppression manuelle d'une image de profil : actualiser son manifeste
composer images:manifest

= En production : APP_ENV=production et APP_DEBUG=false, puis compiler le bootstrap sur le serveur cible
composer bootstrap:cache

= Originaux conservés dans storage\backups\images\ ; état dans storage\thumbnail-optimization.json
= storage\backups\images\manifest.json relie chaque chemin à ses sauvegardes originales

= Sur le serveur déployé, nettoyer régulièrement les anciens bundles JavaScript
composer js:prune

= La rétention démarre lors de la première observation ; suppression après sept jours

= Emplacements
storage\logs\
storage\cache\
storage\sessions\

=========================================
BASE DE DONNÉES
=========================================

= Creer automatiquement un fichier SQL vide (nom en minuscules avec tirets)
composer db:migration -- ajout-table
= Ouvrir le fichier affiche, ecrire le SQL et sauvegarder ; ensuite composer db:migrate.
= Ne pas executer le meme SQL dans /sql avant la migration ; ne pas modifier un fichier deja applique.

= Voir les migrations et leur etat (base du .env, lecture seule)
composer db:migrate:status

= Appliquer les migrations manquantes apres sauvegarde
composer db:migrate

= Enregistrer une migration deja appliquee, sans rejouer le SQL (verification manuelle obligatoire)
composer db:migrate:baseline -- YYYY-MM-DD-NN-description.sql
composer db:migrate:baseline -- 2026-10-04-user-ownership.sql

= La cible est la base du .env. Sauvegarder avant db:migrate.
= Une migration failed/running bloque le rejeu : verifier et reparer manuellement avant baseline.
= Ne pas modifier les fichiers SQL deja enregistres ; ajouter une migration corrective.

= Sauvegarder la base avec les paramètres DB du .env
composer backup

= Emplacement des sauvegardes
storage\backups\database\

= Chemin personnalisé de mysqldump si nécessaire
MYSQLDUMP_PATH dans .env
